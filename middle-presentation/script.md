# 중간 발표 대본 (약 9분, 슬라이드 12장, 10분 안에 여유 있게)

## 1. 표지 (0:15)
Prompt Airlock 중간 발표입니다. 공공기관이 외부 LLM 을 쓸 때 질문 속 개인정보가 밖으로 나가지 않게 막는 게이트웨이이고, 10월에는 실제로 동작하는 첫 버전을 만들었습니다.

## 2. 문제 (0:35)
화면 예시처럼 이름, 소속, 전화번호가 섞인 질문이 그대로 외부 회사로 갑니다. 지우면 질문의 뜻이 사라지고요. 보안 지침도 입력과 답의 민감정보를 막으라고 요구합니다.

## 3. 해결 방향 (0:40)
그래서 지우지 않고 가명으로 바꿔 보냅니다. 외부 LLM 은 가명만 보고, 답에 담긴 가명은 저희가 원래 값으로 되돌립니다. 가명과 원래 값의 짝은 기관 안의 Vault 라는 별도 프로그램에만 있습니다.

## 3-1. Vault (0:35)
가명의 짝은 Vault 라는 작은 프로그램에 따로 보관합니다. 민감한 값을 다루는 부분이라 메모리 실수를 막아 주는 Rust 로 만들었고, 같은 컴퓨터 안에서 실행한 사용자만 접근할 수 있습니다. 가명은 질문마다 새로 만들고, 질문이 끝나면 짝을 지우고 메모리도 0 으로 덮어씁니다.

## 4. 기존 도구 (0:40)
LiteLLM 은 여러 LLM 회사를 같은 방식으로 쓰게 해 주는 중간 서버이고, 검사 프로그램을 끼울 수 있습니다. 그 검사 프로그램으로 많이 쓰는 것이 Presidio 이고, 개인정보를 찾고 바꾸는 두 단계로 되어 있습니다. 다만 기본이 영어라 한국 형식은 직접 넣어야 합니다.

## 5. 차이 (0:40)
저는 한국 형식과 한국어 이름 모델을 처음부터 넣었고, 가명 짝은 별도 프로그램에 둡니다. 가장 큰 차이는 검사 도구가 고장 났을 때 무조건 막는다는 점입니다. 답도 다시 검사하고, 기밀 문서는 아예 보내지 않습니다.

## 6. 처리 순서 (0:45)
등록된 앱인지와 문서 등급을 확인하고, 개인정보를 찾아 가명으로 바꾼 뒤 한 번 더 확인합니다. 모두 통과해야 밖으로 나가고, 답은 검사한 뒤 되돌립니다. 하나라도 실패하면 그 자리에서 거절합니다.

## 7. 가명 과정 (0:30)
가명이 한 글자라도 바뀌면 되돌리지 않고, 답의 링크 안에 가명이 있으면 답 전체를 막습니다. 링크를 누르는 순간 원래 값이 새어 나가기 때문입니다.

## 8. 건너뛸 수 없게 (0:35)
검사 순서를 프로그램의 타입으로 강제해서, 검사를 건너뛴 코드는 아예 만들어지지 않습니다. 이름 모델이나 Vault 가 멈추면 보내지 않습니다.

## 9. 시연 (2:00)
실제로 띄워 보겠습니다. 등급 S 는 바로 막고, 주민번호는 종류만 알려 주며 막습니다. 이름과 전화번호는 오른쪽처럼 가명으로 나가고, 받은 답에서는 원래 값으로 돌아옵니다. 링크 속 가명, base64 로 숨긴 주민번호, 바뀐 가명도 모두 막습니다. (현장 시연이 안 되면 슬라이드 영상 재생)

## 10. 검증 결과 (0:40)
자동 시험 325개가 통과했고, 사람 이름은 98.7% 를 찾았습니다. 시연에서 원래 값이 밖으로 나간 경우는 없었고, 짧은 질문 처리 시간은 21.6 ms 로 LLM 응답 시간에 비해 작습니다.

## 11. 정리와 계획 (0:30)
감사 기록과 운영 기능까지 마쳤고, 아직 이름 2.2% 는 놓쳐서 기관 보호어 목록으로 보완합니다. 다음은 시간 제한, 실제 provider 연결, 평가입니다. 감사합니다.

## 예상 질문(짧게)
- 왜 Presidio 를 그대로 안 썼나: 한국 형식, 고장 시 거절, 답 속 링크 검사가 필요해서 직접 만들고 구조는 참고했습니다.
- 2.2% 는 괜찮나: 주민번호 같은 차단 대상은 규칙으로 막고, 놓치는 것은 이름이며 보호어로 줄입니다.
- 실제 LLM 은: 같은 통신 코드라 주소와 열쇠만 바꾸면 됩니다.

## 시연 준비(발표 전)
