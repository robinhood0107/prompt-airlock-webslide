# 중간 발표 대본 (약 10분, 슬라이드 15장)

## 1. 표지 (0:20)
안녕하세요. Prompt Airlock 중간 발표를 시작하겠습니다. 공공기관 직원이 인터넷으로 쓰는 대화형 언어모델, 즉 외부 LLM 을 쓸 때 질문 속 개인정보가 밖으로 나가지 않게 막는 프로그램입니다. 10월에는 질문을 넣고 답을 받기까지 실제로 동작하는 첫 버전과, 기록·운영 기능까지 만들었습니다. 문제, 용어, 기존 도구, 차이, 처리 순서, 시연, 결과, 다음 계획 순서로 말씀드리겠습니다.

## 2. 문제 (0:45)
화면의 예시처럼 "한빛시청 김민준 주무관에게 010-2345-6789 로 회의 일정을 알려 주는 안내문을 써 줘"라고 물으면, 이름과 소속, 전화번호가 그대로 외부 회사 서버로 갑니다. 그렇다고 이 정보를 지우면 누구에게 어디로 연락하라는 건지 알 수 없어서 쓸 만한 답이 나오지 않습니다. 국가정보원 가이드라인과 N2SF 도 외부 LLM 에 보내는 입력과 받은 답에서 민감정보를 찾아 막으라고 요구합니다.

## 3. 해결 방향 (0:45)
그래서 지우지 않고 바꾸기로 했습니다. 보내기 전에 개인정보 자리를 찾아 임의 문자열, 즉 가명으로 바꿉니다. 김민준은 PERSON 으로 시작하는 문자열이 되고, 전화번호는 KOREAN_PHONE 으로 시작하는 문자열이 됩니다. 외부 LLM 은 가명이 든 질문을 받고 답에도 같은 가명을 넣어 돌려줍니다. 그러면 저희가 가명을 다시 원래 값으로 바꿔 직원에게 전달합니다. 가명과 원래 값의 짝은 기관 안의 별도 프로그램에만 저장하기 때문에, 외부에서는 가명만 보고 원래 값을 알 수 없습니다.

## 4. 용어 (0:50)
앞으로 나올 말을 정리하겠습니다. provider 는 외부 LLM 을 빌려주는 회사입니다. 게이트웨이는 직원의 앱과 provider 사이에서 요청을 대신 전달하는 서버로, 모든 질문이 여기를 지나가니 한곳에서 검사할 수 있습니다. 탐지는 질문에서 개인정보 위치를 찾는 일이고, NER 은 문장 속 사람이나 기관 이름을 찾도록 학습된 모델입니다. 전화번호는 모양이 정해져 있지만 이름은 그렇지 않아서 이 모델을 씁니다. token 은 가명, Vault 는 가명의 짝을 보관하는 별도 프로그램입니다. fail closed 는 검사 도구가 고장 나거나 결과가 불확실하면 보내지 않는 쪽을 택한다는 원칙입니다.

## 5. LiteLLM (0:40)
이미 쓰이는 도구를 먼저 보겠습니다. LiteLLM 은 여러 회사의 provider 를 같은 형식으로 쓸 수 있게 해 주는 공개 중간 전달 서버입니다. 보내기 전과 받은 뒤에 검사 프로그램을 끼울 수 있는데, 이것을 가드레일이라고 부릅니다. 개인정보를 가릴 때는 Presidio 를 별도 서버로 띄워 부르고, 옵션을 켜면 답 속의 가린 자리를 원래 값으로 되돌려 줍니다.

## 6. Presidio (0:40)
Presidio 는 Microsoft 가 공개한 개인정보 도구로, 찾기와 바꾸기 두 부분으로 되어 있습니다. 찾기는 글자 모양 규칙, 번호 검산, NER 을 쓰고, 바꾸기는 다른 글자로 치환하거나 별표로 가리거나 암호화합니다. 다만 LiteLLM 연동의 기본 언어가 영어라서 주민등록번호나 국내 전화번호 같은 한국 형식은 직접 규칙을 만들어 넣어야 합니다. 저도 이 찾기와 바꾸기 구조를 그대로 따랐습니다.

## 7. 차이 (0:50)
표의 오른쪽이 이 프로젝트입니다. 한국 형식과 한국어 NER 을 처음부터 넣었고, 가명의 짝은 별도 프로그램에 두었다가 요청이 끝나면 지웁니다. 가장 큰 차이는 검사 도구가 고장 났을 때입니다. 저는 무조건 거절합니다. 받은 답도 다시 검사한 뒤에만 되돌리고, 기밀 등급 문서는 아예 밖으로 보내지 않습니다.

## 8. 처리 순서 (1:00)
질문 하나가 지나가는 8단계입니다. 먼저 암호화된 연결인지, 등록된 앱인지 확인하고, 문서 등급이 C 나 S 면 여기서 끝냅니다. 다음으로 개인정보를 찾고, Vault 에서 가명을 받아 바꾼 뒤, 바꾼 질문에 원문이 남아 있는지 한 번 더 찾습니다. 여기까지 모두 통과해야 provider 로 보냅니다. 답이 오면 위험한 내용이나 링크를 검사하고, 이번 요청에서 만든 가명만 원래 값으로 되돌립니다.

## 9. 가명이 오가는 과정 (0:45)
애니메이션처럼 밖으로는 가명만 나가고, 답에서 원래 값으로 돌아옵니다. 가명이 한 글자라도 바뀌면 비슷해 보여도 되돌리지 않습니다. 다른 사람의 값이 잘못 들어가는 사고를 막기 위해서입니다. 그리고 답의 링크 주소 안에 가명이 있으면 답 전체를 거절합니다. 직원이 링크를 누르는 순간 원래 값이 외부 사이트로 넘어갈 수 있기 때문입니다.

## 10. 검사를 건너뛸 수 없게 만든 방법 (0:50)
사람이 실수로 검사를 빼먹는 일도 막았습니다. 프로그램에서 값의 종류를 구분하는 표시를 타입이라고 하는데, 질문을 네 가지 타입으로 나눴습니다. 질문은 원본, 등급 확인, 가명 처리, 최종 검사 통과 순서로만 바뀔 수 있고, provider 로 보낼 요청은 마지막 타입으로만 만들 수 있습니다. 순서를 건너뛴 코드는 컴파일 단계에서 오류가 나서 아예 만들어지지 않습니다.

## 11. 고장 나면 보내지 않기 (0:40)
NER 모델이 멈추면 개인정보를 다 찾았는지 알 수 없으니 거절합니다. Vault 가 멈추면 가명을 받을 수 없으니 거절하고, 가명으로 바꾼 뒤에도 원문이 남아 있으면 거절합니다. 세 경우 모두 provider 를 한 번도 부르지 않는다는 것을 시험으로 확인했습니다.

## 12. 기록과 운영 (0:45)
기관에서 실제로 쓰려면 기록이 필요합니다. 요청마다 언제, 어느 앱이, 어떤 결과였는지 한 줄씩 남기고, 원래 값은 남기지 않습니다. 밖으로 실제로 보낸 가명 질문과 받은 답은 1년 이상 보관합니다. 각 줄에는 앞 줄 내용을 요약한 해시를 함께 적어서, 누가 중간 줄을 고치거나 지우면 검증 명령에서 바로 드러납니다. 기록 열람은 서버에서만 명령어로 하고, provider 열쇠는 암호화된 파일로만 보관합니다.

## 13. 시연 (2:00)
이제 실제로 띄워 보겠습니다. 터미널 A 에는 시험용 provider, B 에는 게이트웨이를 띄우고, C 에서 질문을 보냅니다. 옆 창에는 provider 가 실제로 받은 내용이 보입니다.
1. `./ask.sh "회의 안건 정리" S` → S 등급이라 403 으로 거절되고, provider 쪽에는 아무것도 오지 않습니다.
2. `./ask.sh "제 주민번호는 900101-1234567 이고 카드는 4111-1111-1111-1111 입니다"` → 400 으로 거절되고, 주민번호와 카드번호라는 종류만 알려 줍니다.
3. `./ask.sh "한빛시청 김민준 주무관에게 010-2345-6789 또는 user1@example.invalid 로 회의 일정을 알려 주세요"` → provider 쪽에는 가명만 보이고, 제가 받은 답에는 원래 이름과 번호가 돌아와 있습니다.
4. `./ask.sh "[링크] 김민준 주무관 연락처 010-2345-6789 자료 정리"` → 시험용 provider 가 일부러 가명을 링크 주소에 넣어 답했고, 게이트웨이가 답 전체를 막았습니다.
5. `./ask.sh "확인 부탁: OTAwMTAxLTEyMzQ1Njc="` → 이 글자는 주민번호를 base64 라는 방식으로 숨긴 것인데, 풀어서 찾아 거절합니다.
6. `./ask.sh "[변형] 김민준 주무관 연락처 010-2345-6789 전달"` → 가명 한 글자가 바뀐 답은 되돌리지 않고 거절합니다.
- 현장 시연이 안 되면 이 슬라이드의 영상으로 설명합니다. 같은 명령을 실제로 실행해 기록한 결과입니다.

## 14. 검증 결과 (1:00)
자동 시험 325개가 모두 통과했고, 무작위 입력을 수백만 번 넣는 시험도 통과했습니다. 시험 문장 300개 속 사람 이름의 98.7% 를 찾았고, 시연 6개에서 원래 값이 밖으로 나간 횟수는 0 입니다. 짧은 질문 하나를 처리하는 데 100번 중 95번은 21.6 ms 안에 끝나서, LLM 이 답하는 몇 초에 비하면 작습니다. 8개 요청을 동시에 계속 보내도 오류 없이 초당 약 115개를 처리했습니다. 숫자는 모두 저장소 이슈에 원자료와 함께 남겼습니다.

## 15. 한계와 계획 (0:40)
아직 이름 600개 중 13개는 찾지 못합니다. 기관과 거래처 이름을 보호어 목록에 넣어 보완합니다. 더 큰 NER 모델 두 개도 비교했는데, 조금 더 잘 찾지만 10배 이상 느려서 지금 모델을 유지했습니다. 다음 단계는 요청마다 처리 시간 제한, 실제 provider 연결, 사용성 평가입니다. 감사합니다.

## 예상 질문
- 왜 C++ 와 Rust 를 썼나: 게이트웨이는 빠르고 메모리를 직접 다뤄야 해서 C++, 가명의 짝을 지키는 Vault 는 메모리 실수가 없어야 해서 Rust 로 따로 만들었습니다.
- 왜 Presidio 를 그대로 쓰지 않았나: 한국 형식, 고장 시 거절, 답 속 링크 검사가 기본 범위 밖이라 필요한 부분을 직접 만들었습니다. 구조는 참고했습니다.
- 2.2% 를 놓치면 위험하지 않나: 주민번호 같은 차단 대상은 규칙으로 막고, 놓치는 것은 이름입니다. 보호어 목록으로 줄입니다.
- 느려지지 않나: 짧은 질문 21.6 ms 로 LLM 응답 시간에 비해 작습니다.
- 실제 LLM 은 언제 붙이나: 시험용 provider 와 같은 통신 코드를 쓰므로 주소와 열쇠만 바꾸면 되고, 다음 단계에서 연결합니다.
