# 중간 발표 대본 (약 9분 30초)

## 1. 표지 (0:15)
안녕하세요. Prompt Airlock 중간 발표를 시작하겠습니다. 공공기관이 외부 LLM 을 쓸 때 개인정보가 밖으로 나가지 않게 하는 한국어 보안 게이트웨이이고, 오늘은 끝까지 동작하는 MVP 와 시연까지 보여 드리겠습니다.

## 2. 문제 (0:50)
업무 질문에는 이름, 전화번호, 주민번호가 자연스럽게 섞입니다. 이것이 그대로 외부 LLM 으로 나가는 것이 첫 번째 문제입니다. 그렇다고 지우기만 하면 "누구에게 연락하라"는 질문의 뜻이 사라집니다. 그래서 가명으로 바꿔 보내고, 답에서 원래 값으로 되돌리는 방식을 택했습니다. 국정원 가이드라인과 N2SF 도 입력과 응답의 민감정보 탐지, 정해진 형식만 외부로 보내는 통제를 요구합니다.

## 3. LiteLLM (0:50)
이미 쓰이는 구조부터 보겠습니다. LiteLLM 은 Chat Completions 호환 프록시 하나로 여러 provider 를 중계합니다. 요청 전과 응답 뒤에 가드레일 훅을 끼울 수 있고, 개인정보 마스킹은 Presidio 를 별도 서비스로 불러 처리합니다. output_parse_pii 옵션을 켜면 답에 있는 자리표시자를 원래 값으로 되돌립니다.

## 4. Presidio (0:50)
Presidio 는 두 부분입니다. Analyzer 가 정규식, 체크섬, NER 로 위치를 찾고, Anonymizer 가 치환, 마스킹, 해시 같은 방식으로 바꿉니다. 언어는 설정으로 정하는데 LiteLLM 의 기본값은 영어이고, 주민번호나 국내 계좌 같은 한국 형식은 직접 추가해야 합니다. 범용 도구로서 잘 만든 구조라서 저도 설계의 기준점으로 삼았습니다.

## 5. 차이 (0:50)
같은 문제를 어디서 다르게 풀었는지 표로 정리했습니다. 저는 공공기관 외부 전송 통제 하나만 봅니다. 한국어 형식표와 한국어 NER 을 내장했고, 가명은 요청마다 무작위 token 으로 만들며 매핑은 별도 Rust Vault 프로세스에만 둡니다. 가장 큰 차이는 실패했을 때입니다. 탐지기나 Vault 가 실패하면 저는 무조건 거절하고 provider 는 한 번도 부르지 않습니다. 응답도 다시 검사해서 링크 안에 token 이 들어가거나 token 이 바뀌면 응답 전체를 막습니다.

## 6. 내 설계 (1:10)
처리 순서입니다. TLS 와 출처 인증으로 들어오고, 등급이 C 나 S 면 여기서 끝납니다. 그다음 규칙과 한국어 NER 로 탐지하고, Vault 가 가명을 발급하고, 바꾼 뒤 다시 한 번 원문이 남았는지 잔여 검사를 합니다. 모두 통과해야만 provider 로 나갑니다. 돌아온 답은 다시 탐지해 검사하고, 같은 요청 범위에서 발급한 token 만 원래 값으로 되돌립니다.

## 7. 타입 경계 (0:50)
이 순서를 코드 규칙이 아니라 타입으로 강제했습니다. 질문은 RawPrompt 에서 VerifiedPrompt 까지 네 단계 타입으로만 바뀌고, provider 요청은 VerifiedPrompt 로만 만들 수 있습니다. 순서를 건너뛰면 컴파일이 안 됩니다. 애니메이션처럼 어느 단계에서든 실패하면 provider 호출은 0 입니다.

## 8. 시연 (2:00)
이제 실제로 띄워 보겠습니다. 왼쪽은 게이트웨이, 오른쪽은 mock provider 가 받은 기록입니다.
- `./ask.sh "회의 안건 정리" S` → 403, 기록 없음.
- 주민번호·카드 질문 → 400, 종류 이름만 돌아오고 값은 없습니다.
- 이름·전화·이메일 질문 → 오른쪽 기록에는 token 만, 제가 받은 답에는 원래 값이 있습니다.
- [링크] 질문 → 모델이 token 을 링크 주소에 넣었고, 게이트웨이가 응답 전체를 막았습니다.
- base64 질문 → 감싼 주민번호도 풀어서 찾아 막습니다.
- [변형] 질문 → 한 글자 바뀐 token 은 비슷해도 되돌리지 않습니다.
(실패 대비: 이 슬라이드의 애니메이션과 리허설 출력 화면으로 설명)

## 9. 검증 결과 (1:00)
시험은 319개가 통과했고 sanitizer 와 fuzz 도 돌렸습니다. 한국어 NER 은 최종 셋에서 사람 재현율 0.987, 기관 0.910 입니다. 더 큰 모델 2개도 측정했는데 지연이 10배 이상 늘어서 지금 모델을 유지했습니다. 끝까지 지연은 NER 없이 4 KiB 질문 p95 5.8 ms, NER 포함 짧은 질문 21.6 ms 이고, 동시 8개 요청에서 오류는 0 이었습니다. 숫자는 모두 저장소 이슈에 원자료와 함께 남겼습니다.

## 10. 한계와 계획 (0:40)
아직 600개 중 13개 이름이 가려지지 않습니다. 기관 이름과 거래처를 보호어 목록으로 넣어 보완합니다. 다음은 감사 기록과 운영 기능, 요청 단위 시간 상한, 실제 provider 연결과 평가입니다. 감사합니다.

## 예상 질문
- 왜 C++ 와 Rust 인가: 게이트웨이는 지연과 메모리 통제가 필요해 C++, 매핑을 지키는 Vault 는 메모리 안전성이 중요해 Rust 로 분리했습니다.
- 왜 Presidio 를 그대로 쓰지 않았나: 한국어 형식과 실패 시 거절, 응답 링크 검사가 기본 범위 밖이라 필요한 부분만 직접 만들었습니다. 구조는 참고했습니다.
- 2.2% 누락은 괜찮은가: 이름 하나가 남는 것이고 차단 대상(주민번호 등)은 규칙으로 막습니다. 보호어 목록으로 줄입니다.
- 지연은: NER 포함 짧은 질문 21 ms 로 LLM 응답 시간에 비해 작습니다.
- 실제 provider 는: mock 과 같은 HTTPS 클라이언트를 쓰므로 주소와 자격 증명만 바꾸면 됩니다. 다음 단계에서 연결합니다.
