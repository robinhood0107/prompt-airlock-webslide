# 중간 발표 대본 (약 9분 40초, 슬라이드 12장)

말투는 처음 듣는 사람에게 설명하듯 쉽게 합니다. 어려운 말은 나올 때마다 한 번 풀어 줍니다.

## 1. 표지 (0:15)
안녕하세요. Prompt Airlock 을 발표하겠습니다. 에어록은 우주선에서 바깥 공기가 섞이지 않게 문 두 개 사이에 두는 작은 방입니다. 이 프로젝트도 기관 안의 질문이 외부 LLM 으로 나가기 전에 개인정보를 걸러 주는 작은 방 역할을 합니다.

## 2. 무엇이 문제인가 (0:50)
공무원이 "김민준 주무관에게 010-2345-6789 로 연락해 달라는 안내문을 써 줘"라고 묻는다고 해 보겠습니다. 이 문장은 그대로 외부 회사 서버로 갑니다. 그렇다고 이름과 번호를 지우면 누구에게 연락하라는 건지 알 수 없는 질문이 됩니다. 그래서 진짜 값 대신 가짜 이름표를 붙여 보내고, 답이 오면 다시 진짜 값으로 바꾸는 방법을 택했습니다. 국정원 가이드라인과 N2SF 도 입력과 답의 민감정보를 찾아 막으라고 요구합니다.

## 3. 먼저 알아 둘 말 (0:45)
세 가지만 기억해 주세요. LLM 과 provider 는 대화형 언어모델과 그것을 빌려주는 회사로, 우리 기관 밖에 있습니다. 게이트웨이는 앱과 provider 사이의 중간 창구로, 모든 요청이 여기를 지나가니 한곳에서 검사할 수 있습니다. 가명 token 은 진짜 값 대신 넣는 이름표이고, 이름표와 진짜 값의 짝은 우리 쪽 금고에만 적어 둡니다.

## 4. LiteLLM (0:45)
이미 많이 쓰는 도구부터 보겠습니다. LiteLLM 은 여러 LLM 회사를 같은 주소로 쓸 수 있게 해 주는 중간 창구 프로그램입니다. 요청 전과 답 뒤에 검문 지점을 끼울 수 있고, 개인정보를 가릴 때는 Presidio 라는 도구를 따로 띄워 부릅니다. 옵션을 켜면 답의 이름표도 진짜 값으로 되돌려 줍니다.

## 5. Presidio (0:45)
Presidio 는 두 부분으로 되어 있습니다. 찾는 쪽은 전화번호 모양 같은 규칙과, 문장 속 이름을 알아보는 이름 인식 모델로 개인정보 위치를 찾습니다. 바꾸는 쪽은 그 자리를 가리거나 바꿉니다. 다만 기본 언어가 영어라 주민번호 같은 한국 형식은 직접 만들어 넣어야 합니다. 잘 만든 도구라서 제 설계도 이 "찾고 바꾸는" 구조를 기준으로 삼았습니다.

## 6. 같은 문제, 다른 선택 (0:50)
두 방식을 나란히 놓았습니다. 저는 공공기관용 하나만 보기 때문에 한국 형식을 기본으로 넣었고, 이름표의 짝은 프로그램 밖의 별도 금고에 둡니다. 가장 큰 차이는 고장 났을 때입니다. 검사기가 고장 나면 저는 무조건 막습니다. 답도 다시 검사한 뒤에만 되돌리고, 비밀 등급 문서는 아예 내보내지 않습니다.

## 7. 내 설계 (1:00)
8단계 검문소라고 생각하시면 됩니다. 암호화 연결과 앱 확인, 비밀 등급 확인을 지나고, 개인정보를 찾아 금고에서 이름표를 받아 바꾼 뒤, 원문이 남았는지 한 번 더 찾습니다. 여기까지 모두 통과해야만 provider 로 나갑니다. 답이 오면 다시 검사하고, 같은 요청에서 만든 이름표만 진짜 값으로 되돌립니다. 하나라도 실패하면 막는데, 이것을 fail closed, "모르면 닫는다"라고 합니다.

## 8. 가명이 오가는 모습 (0:40)
애니메이션을 보시면 이름과 번호가 이름표로 바뀌어 나가고, 답에서 다시 원래 값이 됩니다. 이름표가 한 글자라도 바뀌면 비슷해 보여도 되돌리지 않습니다. 엉뚱한 사람의 값이 들어가는 사고를 막기 위해서입니다.

## 9. 실수를 코드가 막게 하기 (0:50)
사람이 실수로 검사를 건너뛰는 일을 프로그램 구조로 막았습니다. 질문은 서류처럼 네 단계 도장을 차례로 받고, 마지막 도장이 찍힌 서류만 밖으로 보낼 수 있습니다. 순서를 건너뛰면 프로그램이 아예 만들어지지 않습니다. 그리고 검사기나 금고가 고장 나도 "그냥 보내기" 길이 없습니다.

## 10. 시연 (2:00)
이제 실제로 띄워 보겠습니다. (터미널 A: mock provider, B: 게이트웨이, C: 요청, 옆 창: `tail -f egress.jsonl`)
1. `./ask.sh "회의 안건 정리" S` → 비밀 등급이라 403, 밖으로 나간 기록 없음.
2. `./ask.sh "제 주민번호는 900101-1234567 이고 카드는 4111-1111-1111-1111 입니다"` → 400, 종류 이름만 알려 줍니다.
3. `./ask.sh "한빛시청 김민준 주무관에게 010-2345-6789 또는 user1@example.invalid 로 회의 일정을 알려 주세요"` → 오른쪽 기록에는 이름표만, 받은 답에는 진짜 값.
4. `./ask.sh "[링크] 김민준 주무관 연락처 010-2345-6789 자료 정리"` → 모델이 이름표를 링크 주소에 넣어서 답을 막습니다. 링크를 누르는 순간 진짜 값이 밖으로 새기 때문입니다.
5. `./ask.sh "확인 부탁: OTAwMTAxLTEyMzQ1Njc="` → base64 로 포장해 숨긴 주민번호도 풀어서 찾습니다.
6. `./ask.sh "[변형] 김민준 주무관 연락처 010-2345-6789 전달"` → 한 글자 바뀐 이름표는 되돌리지 않습니다.
- 현장 시연이 안 되면 슬라이드의 기록 재생 영상으로 설명합니다(같은 명령을 실제로 실행한 기록).

## 11. 검증 결과 (1:00)
자동 시험 319개가 모두 통과했고, 무작위 입력을 수백만 번 넣는 시험도 돌렸습니다. 사람 이름은 최종 시험 문장 300개 중 98.7%를 찾았습니다. 시연 6장면에서 밖으로 나간 원문은 0건입니다. 속도는 짧은 질문 하나에 21.6 ms 로, LLM 이 답하는 몇 초에 비하면 작습니다. 동시에 8개씩 보내도 오류가 없었습니다. 숫자는 모두 저장소 이슈에 원자료와 함께 남겼습니다.

## 12. 한계와 계획 (0:40)
아직 이름 600개 중 13개는 못 찾습니다. 기관과 거래처 이름을 보호어 목록에 넣어 보완합니다. 더 큰 모델도 시험했는데 조금 더 잘 찾지만 10배 넘게 느려서 지금 모델을 유지했습니다. 다음은 감사 기록과 운영 기능, 요청마다 시간 제한, 실제 provider 연결과 평가입니다. 감사합니다.

## 예상 질문
- 왜 C++ 와 Rust 를 썼나: 게이트웨이는 빠르고 메모리를 직접 다뤄야 해서 C++, 이름표 짝을 지키는 금고는 메모리 실수가 없어야 해서 Rust 로 따로 만들었습니다.
- 왜 Presidio 를 그대로 쓰지 않았나: 한국 형식, 고장 나면 막기, 답 속 링크 검사가 기본 범위 밖이라 필요한 부분을 직접 만들었습니다. 구조는 참고했습니다.
- 2.2% 를 놓치면 위험하지 않나: 주민번호 같은 차단 대상은 규칙으로 막고, 놓치는 것은 이름입니다. 보호어 목록으로 줄입니다.
- 느려지지 않나: 짧은 질문 21.6 ms 로 LLM 응답 시간에 비해 작습니다.
- 실제 LLM 은 언제 붙이나: 시험용 provider 와 같은 통신 코드를 쓰므로 주소와 열쇠만 바꾸면 되고, 다음 단계에서 연결합니다.
