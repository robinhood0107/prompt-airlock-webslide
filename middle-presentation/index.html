개인정보를 가려 주는 "공기 차단실(에어록)"

한국어 개인정보가명으로 바꿔 보내기답에서 되돌리기고장 나면 막기

무엇이 문제인가

그대로 나간다"김민준 주무관에게 010-2345-6789 로 연락" 같은 질문이 외부 회사 서버로 그대로 갑니다.
지우면 뜻이 사라진다이름과 번호를 지우면 "누구에게 연락하라는지" 모르는 질문이 됩니다.
그래서진짜 값 대신 가짜 이름표(가명)를 붙여 보내고, 답이 오면 다시 진짜 값으로 바꿉니다.

공공기관 지침도 "입력과 답의 민감정보를 찾아 막고, 정해진 형식만 밖으로 보내라"고 요구합니다(국가정보원 외부 언어모델 보안 가이드라인, 국가망 보안체계 N2SF).

먼저 알아 둘 말 3개

LLM · provider대화형 언어모델과, 그 모델을 인터넷으로 빌려주는 회사입니다. 우리 기관 밖에 있습니다.
게이트웨이(프록시)앱과 provider 사이에 서서 모든 요청을 대신 전달하는 "중간 창구"입니다. 여기서 검사하면 모든 요청을 한곳에서 통제할 수 있습니다.
가명 token진짜 값 대신 넣는 이름표입니다. 예: 김민준 → ⟦PERSON_PYZHWD8MSY⟧. 짝은 우리 쪽 금고(Vault)에만 적어 둡니다.

이미 있는 도구 ① LiteLLM

무엇인가여러 LLM 회사를 하나의 같은 주소로 쓸 수 있게 해 주는 공개 "중간 창구" 프로그램입니다.
검문 지점(가드레일)요청을 보내기 전(pre_call)과 답을 받은 뒤(post_call)에 검사 프로그램을 끼울 수 있습니다.
개인정보 가리기검사 프로그램으로 Presidio 를 따로 띄워 부릅니다. 옵션(output_parse_pii)을 켜면 답에 있는 이름표를 진짜 값으로 되돌립니다.

출처: LiteLLM 공식 문서 Guardrails › PII Masking (Presidio)

이미 있는 도구 ② Presidio

찾는 쪽(Analyzer)"010-…" 같은 모양 규칙, 숫자 검산, 문장 속 이름을 알아보는 모델(NER, 이름 인식 모델)로 개인정보 위치를 찾습니다.
바꾸는 쪽(Anonymizer)찾은 자리를 가리기·바꾸기·암호화 같은 방법으로 처리합니다.
한국어에서는LiteLLM 연동의 기본 언어가 영어(en)라서 주민번호·국내 계좌·전화 같은 한국 형식은 직접 만들어 넣어야 합니다.

Microsoft 가 공개한 잘 만든 범용 도구입니다. 제 설계도 이 "찾기 → 바꾸기" 구조를 기준점으로 삼았습니다.

들어오기

  1. 암호화 연결·앱 확인
  2. 비밀 등급 확인

가리기

  1. 개인정보 찾기(규칙 + 한국어 이름 인식 모델)
  2. 금고에서 가명 받기
  3. 남은 원문 다시 찾기

보내고 받기

  1. provider
  2. 답 검사
  3. 같은 요청 것만 되돌리기

가명이 오가는 모습

  • 밖으로는 이름표만 나갑니다
  • 답이 오면 같은 요청에서 만든 이름표만 진짜 값으로 바꿉니다
  • 한 글자라도 바뀐 이름표는 비슷해도 되돌리지 않습니다(엉뚱한 값이 나가지 않게)

실수를 코드가 막게 하기

타입 = 서류 도장질문은 4단계 "서류"로만 바뀝니다. 마지막 도장(VerifiedPrompt)이 찍힌 서류만 밖으로 보낼 수 있고, 건너뛰면 프로그램이 아예 만들어지지 않습니다(컴파일 실패).
고장 나면 닫기검사기·금고가 고장 나도 "그냥 보내기" 길이 없습니다.

시연: 실제로 띄워서 보낸 6가지 질문

  1. 비밀 등급 S → 403, 바로 막음
  2. 주민번호·카드 → 400, 종류만 알려 줌
  3. 이름·전화·이메일 → 이름표로 나가고 되돌아옴
  4. 답의 링크 안에 이름표 → 답을 막음
  5. base64(글자를 영문·숫자로 바꾼 포장)로 숨긴 주민번호 → 풀어서 찾아 막음
  6. 한 글자 바뀐 이름표 → 되돌리지 않음

실제 게이트웨이(127.0.0.1:18443)와 시험용 provider(19443)를 띄워 보낸 기록을 그대로 재생합니다. 발표 때는 같은 명령으로 현장 시연합니다.
