Prompt Airlock 중간 발표

  • 공공기관용 외부 LLM 개인정보 보호 게이트웨이
  • 10월 진행 결과: 입력부터 응답까지 동작하는 MVP, 감사 기록과 운영 기능 구현

문제

  • 업무 질문에 이름, 전화번호, 주민등록번호가 섞인 채 외부 LLM 으로 전송됨
  • 개인정보를 삭제하면 "누구에게 연락할지" 같은 질문의 의미가 사라짐
  • 방향: 개인정보를 가명으로 바꿔 보내고, 응답에서 원래 값으로 복원

근거: 국가정보원 외부 언어모델 보안 가이드라인(2023), 국가망 보안체계(N2SF) — 입력·응답의 민감정보 탐지와 차단 요구

용어

provider외부 LLM 을 API 로 제공하는 회사. 기관 밖에 있음.
게이트웨이기관 앱과 provider 사이에서 요청을 대신 전달하는 서버. 모든 요청이 거쳐 가므로 한곳에서 검사 가능.
가명 token원래 값 대신 넣는 임의 문자열. 예: 김민준 → ⟦PERSON_PYZHWD8MSY⟧. 원래 값과의 대응은 별도 Vault 프로세스에만 보관.

기존 도구 ① LiteLLM

  • 여러 provider 를 같은 API 형식으로 쓰게 해 주는 공개 프록시 서버
  • 요청 전(pre_call)과 응답 후(post_call)에 검사 기능(가드레일)을 연결할 수 있음
  • 개인정보 마스킹은 Presidio 를 별도 서비스로 호출해 처리, output_parse_pii 옵션으로 응답의 자리표시자를 원래 값으로 복원

출처: LiteLLM 공식 문서 Guardrails › PII Masking (Presidio)

기존 도구 ② Presidio

  • Analyzer: 정규식, 체크섬, NER(문장 속 이름을 찾는 모델)로 개인정보 위치 탐지
  • Anonymizer: 찾은 위치를 치환, 마스킹, 해시, 암호화 등으로 변환
  • LiteLLM 연동의 기본 언어는 영어. 주민등록번호, 국내 계좌·전화 형식은 직접 추가 필요

Microsoft 공개 도구. 본 설계의 "탐지 → 변환" 구조도 이를 참고함

처리 순서

모든 검사를 통과한 요청만 provider 로 전송한다.

어느 단계든 실패하면 요청을 거절한다(fail closed).

입구

  1. TLS·출처 인증
  2. 등급 확인

개인정보
보호

  1. 탐지(규칙 + 한국어 NER)
  2. Vault 가명 발급
  3. 잔여 검사

외부 LLM
및 응답

  1. provider
  2. 응답 검사
  3. 같은 요청 범위에서 복원

가명 처리와 복원

  • 외부로는 token 만 전송
  • 응답의 token 은 같은 요청에서 발급한 것만 복원
  • 한 글자라도 바뀐 token 은 복원하지 않음

타입으로 막는 경계

  • 질문은 RawPrompt → PolicyChecked → Protected → VerifiedPrompt 순서로만 변환
  • provider 요청은 VerifiedPrompt 로만 생성 가능, 단계를 건너뛰면 컴파일 실패
  • 탐지기·Vault 장애 시에도 우회 경로 없음

시연

  1. 등급 S 요청 → 403
  2. 주민등록번호·카드번호 → 400, 종류만 응답
  3. 이름·전화·이메일 → token 으로 전송 후 복원
  4. 응답의 링크 안 token → 응답 거절
  5. base64 로 인코딩한 주민등록번호 → 400
  6. 변조된 token → 복원하지 않음
